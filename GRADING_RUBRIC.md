# Руководство по оцениванию

Основная шкала на 100 баллов и критические требования находятся в
[ASSIGNMENT.md](ASSIGNMENT.md). Этот документ объясняет, как преподаватель
проверяет результат.

## Уровни выполнения

Для каждого раздела используется одинаковый принцип:

- **0% баллов:** компонент отсутствует или не запускается;
- **50% баллов:** компонент работает частично, создавался вручную или не описан;
- **80% баллов:** требования выполнены, но есть небольшие ошибки в качестве,
  безопасности или документации;
- **100% баллов:** решение воспроизводимо, безопасно, задокументировано и студент
  может его объяснить.

## Minimum, standard и advanced

### Minimum — допуск к защите

- приложение работает на localhost через Docker Compose;
- Terraform создаёт основную AWS-инфраструктуру;
- images находятся в private registry;
- frontend и backend работают в Kubernetes;
- RDS не открыт в интернет;
- приложение доступно по AWS Load Balancer URL;
- secrets отсутствуют в Git.

Minimum не гарантирует проходную оценку: применяются баллы и критические
требования из задания.

### Standard — ожидаемый результат

- все обязательные tasks выполнены;
- CI/CD использует GitHub OIDC;
- deployments имеют две Ready replicas, probes и resource limits;
- преподаватель может воспроизвести deployment по README;
- студент демонстрирует rollout, rollback и восстановление Pod;
- после проверки выполнен cleanup.

### Advanced — дополнительный уровень

- custom domain и HTTPS;
- reusable Terraform modules;
- monitoring, centralized logging или HPA;
- image scanning с quality gate;
- демонстрация восстановления backup.

## Правила защиты

1. Защита длится 20–30 минут.
2. Студент использует собственный repository и commit history.
3. Screenshots дополняют, но не заменяют live demonstration.
4. Преподаватель выбирает минимум две команды из acceptance criteria.
5. Студент объясняет решения своими словами; копирование без понимания снижает
   баллы соответствующего раздела.
6. При временной ошибке cloud provider допускаются workflow logs, Terraform
   outputs и evidence, созданные до защиты.

## Академическая честность

Разрешается использовать документацию, поисковые системы и AI-инструменты, если
это соответствует правилам курса. Студент остаётся ответственным за код и должен
уметь объяснить каждый созданный resource, secret flow и deployment step.
